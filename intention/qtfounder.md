# qtfounder：作者的自我操作系统

记录于 2026-08-15（基于 qtfounder 全貌重建，经作者确认）。

## 规划的前提：创作需要系统承载

写小说一开始只是副业尝试。但持续的创作带来持续的问题：情绪和灵感散落在各处，改稿轨迹不可见，创作状态无法回顾，表达没有出口。写作越深入，越需要一个系统来承载它——否则创作只能停留在"写一篇算一篇"。

这是规划的前提：**要让创作成为可持续的、可积累的、可表达的事业，而不是一次性的尝试。**

## 规划的核心：让自我可观测、可运行

作者为此规划了一套完整的架构——四个层次，各自回答一个问题：

```
数据层   fiction + memory（创作产出 + 记忆：方向/方法/事实）  → 有什么
观察层   创作现场（时间线 / 矩阵 / 改稿轨迹）                → 在写什么
服务层   provider API（数据统一出口）                        → 怎么取
分析层   cli 情绪维度量化（git 历史 + LLM）                  → 状态如何
```

这不是工具的自然堆积，而是**有意的系统设计**：每个层次解决一个明确的意图。

## 规划的四重意图

**1. 让创作可观测**
创作现场把"作品集"变成"创作现场"——从展示结果到展示过程。改稿轨迹让创作状态一目了然：写到哪了、哪些成稿、哪些卡住。

**2. 让记忆可积累**
memory 按认知科学框架组织（方向 / 方法 / 事实 / 状态 / 画像）——创作中的体悟不再散落，而是沉淀为可复用的资产。

**3. 让状态可感知**
cli 的情绪维度分析（valence / arousal / warning_signs）把不可言说的情绪状态量化——创作与情绪的关系变得可见，这是"叙事习惯"的度量衡。

**4. 让表达自然生长**
现实体悟进入创作（三天迭代八个产品 → 男主的事业线），创作又反向成为表达（初稿加工发公司账号）——创作、表达、品牌是一体的。

## 闭环：系统如何运行

```
记录情绪（cli）→ 写入创作（fiction）→ 观察轨迹（studio/创作现场）→ 反哺现实
```

元目标是"建立描述现实状况和未来想象的叙事习惯"——平台是让这个习惯**可持续运行的基础设施**，而不是习惯本身。

## 归宿：与公司治理同构

这套个人系统与公司治理是同一个规划思想的两面：

```
公司层：决议档案 → 治理视图（让公司可运行）
个人层：创作/记忆/情绪 → 创作现场（让自己可运行）
```

同一个内核：**把隐性的东西显性化，让系统自己运转**——"公司活过创始人"在个人尺度上的版本，也是"知识资产化"的自我版本。
