# 资产契约与资产目录：扩展性边界评估

记录于 2026-08-15。对 qtfounder 统一资产管理模式（资产契约 + 资产目录）的扩展性评估，经作者确认。

## 模式本质

**资产契约**（配置文件承载语义规则）+ **资产目录**（通用引擎按契约构建目录树）。语义规则从代码移入配置——新增资产 = 新增契约，零代码。

## 强扩展维度（域内扩展性 = 配置性）

| 维度 | 扩展方式 | 程度 |
| --- | --- | --- |
| 新增资产 | 写一个契约 yaml | 无限（journal/report/archive/roadmap 均适用） |
| 层级深度 | levels 数组任意加级 | 任意深度 |
| 命名规则 | pattern 正则任意定义 | 几乎无限 |
| 排序策略 | unsorted 枚举 + sortKey | 3 种内置，可加 |
| 资产语义 | label 自定义 | 无限 |

## 边界（到什么程度为止）

| 边界 | 说明 |
| --- | --- |
| 数据源形态 | 契约隐含"本地文件系统"——远端/API/数据库源不适用 |
| 文件内容 | 契约只解析文件名，不解析内容（frontmatter/元数据） |
| 非目录形态 | 数据库表/API 集合/图谱——完全不同的结构 |
| 操作语义 | 目前只读——写操作是另一维度 |

**一句话边界**：覆盖"本地文件系统为源、目录树为形态、文件名为语义、排序为组织"的资产域。量潮第二大脑恰好全是这种（git 仓库 + 目录树 + md），域内扩展性极强；域外需新机制。

## 判断

- 这套模式是"第二大脑文件资产域"的领域模型——域内扩展性 = 配置性（新资产零代码）
- 边界不是缺陷，是设计克制；不预埋未出现的需求（source/contentParser/operations 等真实需求出现再加）
