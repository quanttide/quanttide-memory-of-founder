# 写作云（qtcloud-write）蓝图

## 产品定义

写作云是一款**以重写为中心**的 AI 辅助创作桌面应用。不是"帮你写"，是"帮你在已有的文本中看清自己写了什么、还有什么没写"。

核心定位：创作情境启发器，而非内容生成器。

## 核心原则

| 不是 | 是 |
|------|----|
| 从零生成故事 | 在已有文本中发现空隙 |
| 帮你写得更快 | 帮你写得更深 |
| 替代作者决策 | 暴露决策空间 |
| 提供"好"的句子 | 提供"未被考虑过"的角度 |

## 为什么是独立桌面应用

写作云的工作流本质上是**单用户、深度沉浸、长会话**的创作模式，与聊天式 AI 的工作语境完全不同：

| 维度 | 聊天式 AI（通用对话） | 写作云（专用工作台） |
|------|---------------------|-------------------|
| 交互焦点 | 问答 | 创作情境引导 |
| 文本状态 | 一次性生成 | 3R 循环迭代 |
| 历史利用 | 当前会话上下文 | Git 版本历史 + 编辑模式分析 |
| 界面布局 | 线性对话流 | 侧栏编辑器 + 情境面板 + 3R 仪表盘 |
| 第三方依赖 | 无 | Git 仓库 |

选择 Flutter 的原因：
- 跨桌面端（macOS / Windows / Linux）统一代码库
- CustomPainter 适合文本高亮、空隙标记等自定义渲染
- 不需要 Web 技术栈即可实现丰富文本编辑体验
- 与 qtgame-war 的技术栈一致（Flutter/Dart），团队经验可复用

## 核心功能模块

### 1. 项目系统

写作云以"项目"组织创作内容，每个项目对应一个本地 Git 仓库。

- 打开项目：选择本地目录，自动检测是否已有 Git 仓库
- 新建项目：初始化 Git 仓库 + 写作云元数据目录（`.qtcloud-write/`）
- 文件管理：Markdown 文件树，按目录结构浏览底稿
- Git 集成（内置）：在应用内完成 add / commit / push / log 查看，无需切换终端

### 2. 创作情境引擎（Creative Situation Engine）

最关键的功能。不是回答问题，是**帮助作者进入一个还没有被写出来的场景**。

输入：当前文本选区 + 3R 阶段上下文
输出：一段情境引导语（沉浸式、空行密集、聚焦于感官和未决定的选择）

设计约束：
- 不替作者决定情节走向，只提问"你想写哪个时刻"
- 引导语中不使用"你应该"句式
- 每次引导专注一个具体的物理空间和时间窗口（不泛化）
- 引导结束后让作者选择从哪个位置进入
- 引导语显示在右侧情境面板中，不与编辑器争夺焦点

### 3. 编辑历史分析器（Revision History Analyzer）

调用 `git log` 和 `git diff`，在应用内渲染分析结果：

- 提交频率热力图（按小时/日分布）
- 删除内容类型分析（对话/描写/内心独白的删除比例）
- 修改方向趋势图（历次提交的叙事方式变化曲线）
- "回头修改同一段"的热点区域标记（在编辑器侧边栏显示彩色标记）

### 4. 空隙检测器（Gap Detector）

在编辑器文本中标记可能被跳过的"半秒钟"，使用 Flutter CustomPainter 在文本上方渲染标记：

- 两个动作之间（"他推开门"和"他看到她"之间的空隙）
- 对话间隙（"嗯"和"好"之间的沉默未被描写）
- 时间跳越处（"第二天清晨"——这一夜未被写）
- 视角切换点（从他转到她时，是否有重叠瞬间）

每个空隙在编辑器左侧显示彩色圆点标记（颜色表示可写性评分：绿→黄→红）。

### 5. 3R 循环管理器

追踪每次 3R 循环的状态，在右侧仪表盘实时显示：

- 当前阶段指示器（Review / Reflection / Rewrite 高亮环）
- 当前循环次数（第 N 轮）
- 周期时长趋势图（三轮是否在逐次缩短）
- 累积修改量（本轮新增/删除字数）
- 阶段切换按钮（手动推进循环）

### 6. 编辑器

基于 Flutter 的自定义文本编辑器（非 WebView），专为 3R 写作优化：

- Markdown 语法高亮
- 空隙标记可视化（左侧 gutter 圆点 + 行内高亮下划线）
- 三版并列视图（同一段落的三个版本并排显示）
- 修改对比模式（当前版本 vs 上一版提交的 diff）
- 无干扰模式（隐藏所有面板，仅显示编辑器）

## 风格档案（Style Profile）

写作云应维护一个可配置的"风格方向"记录，每次反思时对照：

```
当前风格设定示例：
  1. 对话 → 动作          （当前转化率：60%，目标：80%）
  2. 身份标签 → 身体感知   （当前转化率：40%）
  3. 对称叙事 → 交错叙事   （当前转化率：30%）
  4. 命名情绪 → 隐藏情绪   （当前转化率：50%）
  5. 过去闪回 → 碎片插入   （当前转化率：70%）
```

转化率基于当前文本的统计分析。每次 Rewrite 后更新。

## 集成点

| 层 | 集成对象 | 用途 |
|----|---------|------|
| 版本控制 | Git（内置） | 读取提交历史分析编辑模式，应用内 add/commit/push |
| AI | API（可配置端点） | 生成情境引导语、分析文本模式、检测空隙 |
| 文件系统 | 本地目录 | 项目以目录形式组织，与已有工作流兼容 |
| 外部编辑器 | 可选（通过文件系统） | 用户可选择在外部编辑器中修改，写作云检测文件变更后刷新 |

## 实施阶段

### P0 — 最小可行原型（已验证）

当前 Zed + AI 的工作流已经跑通一个完整 3R 循环：

```
输入：已有文本 + "帮助创作者进入创作情境"
交互：AI 情境引导 → 作者在编辑器中改写 → 手动 Git 提交
输出：一次完整的 Review → Reflection → Rewrite 闭环
```

P0 状态：已验证。成本：一次对话的 token + 作者的创作时间。

### P1 — Flutter 桌面应用基础

构建最小可用桌面应用，验证核心交互模式脱离聊天界面后的可行性：

- [ ] Flutter 桌面项目脚手架（macOS 优先）
- [ ] 项目系统：打开本地目录、文件树浏览
- [ ] Git 集成：在应用内执行 add / commit / push / log
- [ ] Markdown 编辑器：基本编辑功能 + 语法高亮
- [ ] 创作情境面板：显示引导语，从 AI API 获取内容
- [ ] 提示词模板库（按体裁分类：小说/随笔/商业写作）

### P2 — 3R 循环核心

- [ ] 评审面板：提交历史可视化、编辑模式分析报告
- [ ] 反思面板：情境引导、盲点提示、风格检查
- [ ] 空隙检测器：CustomPainter 渲染标记（左侧 gutter 圆点）
- [ ] 3R 仪表盘：循环状态追踪、周期时长趋势
- [ ] 风格档案：可视化仪表盘 + 转化率追踪

### P3 — 编辑器深度

- [ ] 三版并列视图
- [ ] 版本对比模式（diff 渲染）
- [ ] 无干扰模式
- [ ] 修改建议内联显示（AI 建议以批注形式出现在文本中）

### P4 — 协作与迭代

- [ ] 创作报告：每次写作会话结束后自动生成 3R 报告
- [ ] 风格迁移：将一个作品的方法论检查清单应用到另一个作品
- [ ] 多人协作：评审者/反思者/重写者角色分离

## 关键指标

| 指标 | 定义 | 当前基线（2026-06-02） |
|------|------|----------------------|
| 3R 周期时长 | 一轮 Review→Reflection→Rewrite 的总时间 | ~45 分钟（含首次方法论探索） |
| 三轮递减率 | 三轮周期是否逐次缩短 | 是：60min → 15min → 5min |
| 空隙发现率 | 每次 Review 发现的"半秒钟"数量 | 1 个/轮 |
| 层状删除次数 | 同一内容被分几次删除 | 2 次（创业对话） |

## 与 qtgame-war 的关系

写作云（qtcloud-write）与 qtgame-war 同属 Flutter 技术栈，可共享：

| 可复用资产 | 说明 |
|-----------|------|
| Flutter 桌面项目模板 | 脚手架、打包配置、CI/CD |
| CustomPainter 渲染经验 | qtgame-war 的六角格地图渲染 → 写作云的空隙标记渲染 |
| 三栏布局模式 | qtgame-war 的 HQ 布局（情报板+地图+命令面板）→ 写作云的三栏布局 |
| GitHub Actions 发布流程 | 可复用同一套自动化构建与发布 |
| Dart 代码规范 | 风格一致的 lint 规则、测试框架 |

两者定位互补不冲突：qtgame-war 面向游戏玩家，写作云面向写作者。
