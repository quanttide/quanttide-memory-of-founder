在知识工程的生命周期里，这个认知密度判断操作属于获取阶段，具体来说，它是获取阶段内部的前置过滤层。

获取阶段的结构被扩展了

我们之前定义的获取是：从高密度信息中降维，产出可供工程使用的低密度信息。

但完整的获取流程，现在可以分解为三个子步骤：

1. 认知密度判断（前置过滤）

· 输入：待加工的原始材料
· 操作：判断这段内容里，有多少是大模型已知的，有多少是新的、独特的
· 输出：密度评级（高/中/低）+ 新信息列表
· 决策：高密度进入下一步，低密度走其他处理路径

2. 信息提取（核心获取）

· 输入：通过过滤的高密度材料
· 操作：从材料中提取关键概念、关系、约束
· 输出：结构化信息片段

3. 降维与分发（获取的出口）

· 输入：结构化信息片段
· 操作：根据任务场景，将信息降维为可执行的指令、检查清单、或知识卡片
· 输出：低密度可执行指令 → 进入建模或抽取

为什么认知密度判断属于获取而不是建模或抽取

· 建模的职责是：有了结构化的信息之后，建立概念框架和关系。它不负责判断原材料质量。
· 抽取的职责是：手持宪法，对现有资产进行对齐和纯化。它也不负责判断原材料质量。
· 获取的职责是：从外部世界把有价值的信息拉进来，转化成系统内部可用的格式。判断“什么信息值得拉进来”，天然属于获取的职责范围。

这意味着什么

你的命令行里，acquire 命令将不只是简单的”读取文件并分类“。它将内置一个智能判断机制：

· acquire 默认执行认知密度检测 + 信息提取 + 降维分发
· 认知密度低的材料，自动标记，走人工复核路径
· 认知密度高的材料，自动进入知识云的建模和抽取流程

这个设计，恰好和你之前做example/platform分离的逻辑一致：在进入生产区之前，加一道门禁。 只不过这次的门禁，守的是知识云流水线的入口，不是代码仓库的入口。

这是一个关键的补充。认知密度回答的是“这个材料对世界来说新不新”，但你没有回答的问题还有另一个：“这个材料对我们来说重不重要”。

认知关联度，就是用来回答第二个问题的。

—

认知关联度的两个维度

你提了两个子指标：相关度和空白度。

1. 相关度：这个材料跟我们在做的事情有关系吗？

一个材料可能认知密度很高——它包含大量大模型不知道的新信息。但如果它跟你当前构建的系统、你在探索的领域、你在解决的问题毫无关系，那它的价值就极其有限。

相关度的判断标准，就是你系统内部已有的知识结构和关注领域。一个材料如果触及了：

· 你正在建模的领域
· 你现有的宪法中未覆盖的边界
· 你roadmap上待解决的问题

那它的相关度就高。反之，即使它再新颖，也可以暂时搁置。

2. 空白度：这个材料覆盖了我们知识体系中的空白吗？

一个材料可能跟我们在做的事情高度相关，但如果我们已经在这方面有很完善的认知——本体已经稳定、实例已经充足——那它带来的增量价值就有限。

空白度衡量的是：这段内容里面，有多少是我们目前知识联合体中缺失的？

· 如果它触及了现有本体无法解释的新现象 → 空白度高
· 如果它提供了现有实例库中没有的新案例 → 空白度高
· 如果它只是在重申我们已经建好的知识 → 空白度低

—

认知密度 + 认知关联度 = 双维前置过滤

这样，获取阶段就有了两个并行的过滤器：

指标 回答的问题 判断方式
认知密度 对大模型来说新不新？ 比对通用知识库
认知关联度 对我们来说重不重要？ 比对系统内部的知识联合体

两者交叉，形成获取的优先级矩阵：

密度 \ 关联度 高关联 低关联
高密度 最高优先级，立即进入抽取 存档备用
低密度 可能是已有知识的复述，暂缓 最低优先级，可丢弃

—

这在DIKW链条中的位置

这两个指标都属于获取阶段的前置过滤。它们不改变链条的结构，只是让获取变得更智能：

```
Materials → [认知密度检测 + 认知关联度检测] → 过滤后的Data → 抽取 → Information → 建模 → Knowledge → Wisdom
```

—

这解决了一个潜在问题

你之前提出的第一个阻碍是“系统依赖天才模式”——担心知识云只能加工你自己的高密度思考，处理不了普通材料。

认知关联度提供了一个新的视角：普通材料即使认知密度低，但如果关联度高（正好填补了我们知识体系的空白），那它仍然值得被抽取。

比如，一个团队成员的周报，单独看密度很低。但如果它记录了客户对某个功能的具体反馈，而这个反馈恰好触及了你产品模型中未被覆盖的一个场景——那它就是高关联的，值得进入抽取流程。

这样，你的系统就不是只能处理天才思考，而是能够从任何材料中识别出对自身有价值的片段。
